## 已确认需求与实现决策

- **已确认**：源文件和纸张对象默认双向关联；离线不丢内容；真正覆盖相同内容的修改须预览；离线超时冻结；删除前让用户选择解除关联或删除源对象。
- **实现决策**：每个源文档与对象使用稳定 UUID。对象保存经过验证的 UTF-16 源区间与精确原文，局部文本差异计算以 Unicode 码点进行。修改后保留完整历史与源快照。FNV 指纹仅为查找提示；重新定位还必须比较完整原文与准确源区间，不能仅凭文件名或指纹建立关系。
- **实现决策**：对已有源对象的保守源文本编辑，不宣称已解析所有 Markdown/TeX 语义。区域中新增复杂语法仍保留原文，不把它伪装为完整原生对象理解。
- **实现决策**：源文件并行改动可证明在不同字符时自动合并。重复符号使字符对应不唯一，或变化过大无法可靠计算时，保留双方并返回 `unverified-correspondence` 校对预览，不捏造精确对应，也不把不确定性伪称已确认的真实冲突。
- **实现决策**：`reconcileNativeLink` 是内存事务规划器。调用方必须把返回的文档和关联状态一起持久化；真实外部文件写入应使用 `commitNativeWriteback`，仅在写入确认后清空队列。写入失败保留原队列、纸张修改和源快照。
- **实现决策**：冻结时保留独立纸张内容、完整源快照和原队列作为恢复记录；之后源恢复也不再自动写回。Mac 同步服务离线不能调用源不可访问计时器。计时只由实际源文件访问失败触发。

## API 与验收

入口位于 `src/formats.ts`，所有状态均可 JSON 序列化：

- `openNative` / `openNativeBytes` / `serializeNative` / `serializeNativeBytes`：原生文本读写；字节 API 严格拒绝非法 UTF-8 并保留 BOM。
- `editNative` / `renameNative`：对象内容修订与重命名，身份不变且保留历史。
- `createNativeLink` / `editLinkedPaper` / `reconcileNativeLink`：纸张与源对象的双向版本协调。
- `commitNativeWriteback`：外部写入确认；写失败不丢队列。写入适配器须检查传入的预期原文/指纹/版本，拒绝已变化的源文件。
- `resolveNativeConflict`：预览后显式选择文本；预览后源再次变化时拒绝使用过期选择。
- `markSourceUnavailable`：实际源文件无法访问时开始计时，并在超过配置时限时冻结。
- `relinkNativeSource`：用户定位移动或重命名文件后，验证完整源原文和源区间。
- `deleteLinkedObject`：显式 `detach` 或 `delete-source`，无默认删除；离线源删除排队，恢复时遇到新修改先预览。

验证命令：


## Android 原生 pending 与源写入协议

每次原生写入前同时检查源 SHA 和 native pending SHA：`getPendingSource` 明确返回存在或不存在，读取失败不能当作不存在。`saveDocumentVersioned` 的空 pending SHA 要求当前没有 native pending，防止另一个写入请求静默覆盖待写回版本。

自动重试严格验证 native pending 的**全文和原始基准 SHA**均属于本工程持久化的 `plannedWrite`。失败后即使 B 已出现新修订，也先保序完成旧 payload，读回整个源文件精确确认后再处理新 B；不能把新 B 直接替换未知或较旧的 native pending。源全文已等于旧目标时，在 pending CAS 成功后幂等确认，避免重复改写。

未知 pending、源已偏离原基准/目标，或身份仍待确认时，保存源全文与 native pending 全文，显示“预览原生待写回”。用户可以采用待写回版本、保留源文件或手工协调全文。决议先持久化，再用预览的两侧 SHA 做 CAS；原 native pending 由桥归档。预览过期时拒绝覆盖并保留手工输入。全文决议得到实际源读回确认后，仍需重新定位纸张对应对象，不把任意全文变化伪装成精确对象映射。

生产文件层在写实际源文件前提交 pending，使用同目录临时文件、文件 `fsync`、原子替换和父目录 `fsync`，由进程内静态锁保护。已提交 pending 必须通过 URI、文件名和全文摘要校验；损坏时拒绝覆盖并保留原文件，列表用 `diagnostics`/`needsRecovery` 单独报告，不能把损坏或读取失败当作不存在。未提交 `.tmp` 不进入正常队列。旧 `resolveSourceConflict` 单 SHA 接口拒绝执行，显式决议使用 `saveDocumentVersioned`。

只有实际源读取失败标记 `unavailable: true`。非法 UTF-8、超限、写权限或本地日志问题不能启动源失联计时；已观察到源可读时以 `sourceReachable` 或本轮读取记录清除旧期限。之后若再发生真实源访问失败，以新的失败时间开始计时，不能沿用恢复之前的失联期限。

## 尚待验证的高风险目标

1. **Android 独立原生文件往返**：Android 模拟器的生产文件层已通过上述 71 项断言；完整 React/JavaScript/SAF 选择器链路、真实设备与系统文档提供者的读改写重开仍未验，不能以文件层专项代替这些目标。
2. **文件监控和持久访问权限**：已接入 Android 桥的定时/焦点轮询和显式重选源文件；OS 文件事件监控、SAF document-id/URI 的长期生命周期、各文档提供器的移动与删除行为、失效权限恢复仍需真机验证。浏览器本地文件输入保存的是源快照，没有静默写回用户文件系统的能力。
3. **外部应用并行写入**：真实文件写入适配器必须做预期版本比较并保留历史；非协作第三方应用仍可能在读取与写入间竞争。跨平台锁、原子替换与可恢复源版本需继续验证；当前内核不是对所有文件系统的原子写保证。
4. **外部文件修改后的对象身份**：已绑定对象通过当前内核修订保持 UUID。全源内容相同时复用身份；目标精确原文和前后上下文唯一匹配时可以识别未变化的目标；目标本身变化、结构变化或身份不唯一时必须由用户选择候选对象。已验证这些协调算法与模拟桥交互；任意第三方文件结构重写的自动识别仍需持久侧车标识或更强格式对象身份，不使用旧坐标猜测。
5. **复杂格式完全原生兼容**：Office/Apple 格式仍是最终交付目标，须分别引入真实文件语料和读入—修改—写回—原生应用重开验收，并逐对象语义登记。动画、母版等没有证据前必须保持“未验证”。
