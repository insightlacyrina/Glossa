# 知识块结构管理

已确认需求：Android 平板允许手动创建、拆分和合并知识块；知识块可跨页且不得嵌套；知识逻辑关系与 A 纸面空间独立，可跨笔记关联。手机/Mac 只能修订既有块内容，不能通过此入口改变知识块结构。

实现：`BlockManager.tsx` 提供平板专用的拆分、合并及建立关联界面。拆分以既有块的段落/公式/引用为选择单位，只能移动非空真子集；显示保留块与新块的文字和只读 A 对象对照预览。合并至少选择两个块，按笔记中的语义顺序预览并保留稳定段落身份。跨笔记关联显示双方内容及原稿预览。上述操作均不调用 A 移动、排版或页面重排。

实现决策：合并以第一个块身份作为生存者，旧块身份保留别名并重写入边/出边；旧结构及版本保存在档案及操作日志。拆分保留原块已有出边，新块不猜测继承哪些知识关系。组件不提供删除知识块或未经实现的关系移除按钮。这些结构决策与具体 API 见 `domain.ts`。

窗口打开时捕获块内容和相关 A 对象版本。提交前仅校验涉及的块及其源对象；发生相关变更时阻止提交、保留名称和选择，用户可显式“更新预览”后重新确认。无关后续笔迹不被覆盖，也不会因全篇修改时间改变而阻塞该操作。phone/mac 权限在组件外层和领域方法双重检查。

证据：`node tests/block-manager.browser.mjs` 在真实 Chromium 验证 7 项：跨页拆分身份与 A 不变；合并语义顺序、关系及 A 不变；跨笔记关联；旧 B 预览拒绝并保表单及刷新恢复；旧 A 版本拒绝；无关后续笔迹保留；phone/mac 无入口组件及 Escape 关闭、零运行时错误。测试使用真实 `NotebookEngine` 和当前 React 组件。

`tests/integration-sync.test.ts` 的普通与加密 HTTP 链路另覆盖拆分/合并后的别名、旧结构档案、段落身份和完整工程恢复。领域内的并行结构变更冲突测试见 `tests/domain.test.ts`。Android 真机触控、语音无障碍操作和大规模块列表性能仍待验证；当前拆分单位为段落/公式/引用，尚无在该窗口内把一个段落内部再切分的操作。
