## 实际原生窗口

Computer Use 操作打包后的 `.app`，使用 `/private/tmp/glossa-ui-20261022` 独立资料库：

1. 载入示例工程，检查笔记列表、原生纸张、A/B 对照，以及文字、公式、笔迹预览。
2. 用 NSTextView 实际选区把“一个瞬间”替换为“每个瞬间🙂”。B 保存正确，A 在原位置显示印刷层；修订历史保留修改前后内容。
3. 离线对“曲线下的面积”选择“会了”，待复习数从 2 变为 1，保存独立自评事件。
4. 通过 NSSavePanel 导出 `.glossa`，用现有内核重新导入核对。导出与耐久工作区相同；原工程 71 条操作载荷逐项不变，总计 74 条，新增一条 B 修订和两条复习设置/事件。见 [机器核对](ui-export-verification.json)。
5. 退出应用，重启 release 包并使用同一目录。原生窗口仍显示修订后的文字、29 个可见原稿对象和 1 项待复习。
6. 用 NSOpenPanel 打开刚导出的工程，选择“保存当前恢复副本并导入”。A/B 恢复正确，恢复列表显示导入前完整副本；副本文件与先前工作区一致。

保存面板关闭后曾出现 Computer Use 无障碍树读取超时；输出文件已独立核对，进程采样显示主线程正常等待事件。重启重新绑定后可继续操作。未将这一工具超时当作全部系统面板兼容性验收通过。

最后一次命令行启动直接读取工程路径时，采样发现主线程停在系统文件打开调用。最终实现将读取放入后台，并在窗口出现后执行可选启动导入，提供读取进度与取消入口，取消/工作区切换后拒绝迟到结果。最终包另用 `/private/tmp/glossa-cancel-ui-20261022` 验证文件读取失败清楚报错、工作区保留为空；随后经系统面板导入成功，再次用真实选区把 🙂 改为 😀 并保存成功。该保存实际携带字符 ID/版本及全文校验。已有知识块关联点击后滚动定位，知识块复习按钮进入对应块的全部复习视图，也已通过原生窗口核对。
