## 数据不变量与权限边界

1. 成功告知保存之前，变更必须已进入可靠本地持久化路径；持久化失败不能显示已保存。A 的唯一内容来源不能是预览图。
2. ID 一经分配不随重排、重识别、分页或同步变化。B 的映射只引用实际存在的对象或字符；不确定程度必须显式记录。
3. 任何自动识别结果不能覆盖原始笔迹。公式和知识事实不能被错别字规则自动更改。
4. 同步幂等且保留因果依赖；非重叠字符编辑必须共存。冲突保留双方原始操作，解决前不允许静默择一。
5. 未合并修订的独立撤销仅移除这次有效修订及其安全逆变更；依赖冲突必须交给用户。合并后不能仍保留可执行的专用逆记录。
6. 手机与 Mac 对已有 B 的内容修订不包含新建笔记、新增块、删除块、拆块、合块等结构授权。UI 隐藏按钮不能代替内核权限校验。
7. 源文件离线时保留完整可用快照及待写回操作；Mac 同步服务器离线不能触发源文件超时冻结。
8. E2EE 模式中服务器只处理密文；若另行授权服务器明文代理 AI，授权范围、期间与撤销必须明确，不得继续宣称服务器始终不可读。
9. 完整导出应能恢复 A/B、映射、历史、同步状态、复习状态和外部依赖，不只是正文导出。

## 当前实现决策（并非新增产品要求）

- 使用共享 TypeScript 内核和 React 交互客户端；使用本地严格事务存储、不可变事件和工程世代 CAS。失败的多步骤内存操作整体回滚；保存成功后才报告已存。
- 跨重载的未完成笔迹保存为独立检查点；没有证据证明原窗口停止时不抢占其草稿，恢复入口要求显式确认原窗口已停止。该保守选择保护多窗口书写，不改变不丢原始内容的目标。
- Android 使用原生容器承载共享交互与数据内核，并通过原生文件选择/写回接口处理用户授权文件。容器存在不代表 Android 的全部手写体验已验收。
- Mac 同步服务是独立的 Node 进程，客户端不自动获得服务器权限。互联网部署要求用户控制的安全传输入口。
- 优先实现 Markdown/LaTeX 的原文区间编辑，复杂封装格式按真实往返测试逐步扩展。它们仍属于最终目标。
- 在可靠仿手写生成器可用前，B→A 使用已确认的可编辑印刷修订层兜底，并明确保持待生成状态。

## 高风险目标的准入证据

| 目标                  | 不能接受的替代证据                        | 至少需要的证据                                                                 |
| --------------------- | ----------------------------------------- | ------------------------------------------------------------------------------ |
| 自然可靠 Android 手写 | 浏览器鼠标画线或模型字段有 pressure       | 真机不同触控笔的压感/倾斜/掌触/延迟/长笔记/故障恢复                            |
| 精确字符/符号映射     | bbox 重叠、文本相似、用户无法检查的置信分 | 可定位原始笔迹对象，字符来源可复核；不确定明确待校对                           |
| 风格仿手写            | 斜体字体或位图贴图                        | 生成独立可编辑笔迹，样本不足降级，质量/失败/重试评估                           |
| 复杂原生格式兼容      | PNG/PDF 截图或能解 ZIP                    | 原文件读入、对象修改、写回、目标应用重新打开，并比较未知部件、母版/动画/公式等 |
| Mac 公网同步          | Linux localhost 请求成功                  | 真实 Mac、跨互联网客户端、TLS、认证、睡眠恢复、断线重试、备份恢复              |
| 普通故障不丢笔迹      | 单次 reload 成功                          | 提交中断、进程强杀、磁盘满/配额失败、损坏与快照恢复；真实设备耐久测试          |
