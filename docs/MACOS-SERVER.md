# Mac 本机服务器管理

原生应用内的“设置 → 管理这台 Mac 上的服务器”提供完整的本机管理入口。客户端采用 SwiftUI/URLSession/CryptoKit；服务使用内置 Node.js 24、SQLite 和 launchd。首次初始化后，服务运行时独立保存在应用支持目录，关闭阅读客户端不会停止服务。

## 日常使用

1. 双击桌面的 `启动笺注.command`。源码目录移动后，需要更新该文件指向的 `scripts/launch-macos.sh` 路径。
2. 打开应用设置，进入“管理这台 Mac 上的服务器”，选择未占用的端口，点击“初始化新服务器”，再点击“启动服务”。初始化不会读取或覆盖仓库原有的 `server-data/`。
3. 在“服务与工程”查看实际状态、进程、已归档工程及操作数量。点击“连接当前工程到本机”后，回到同步设置核对工程身份、普通/E2EE 模式并保存连接。填入连接不改变现有加密模式，也不自动提交口令。
4. 如需每次登录后运行，手动打开“登录此 Mac 后启动服务”。未打开时，本次已启动的服务仍独立运行，直到手动停止、注销或关机。
5. 在“备份与恢复”手动创建、校验和恢复快照；在“服务器配置”调整端口、备份间隔及保留数量。运行中的配置更改需明确选择保存并重启。

桌面命令只是打开应用；它不会自动初始化或变更服务器。当前 `.app` 已包含服务器所需的 Node 二进制、服务源码及生产阅读端，使用安装包无需另装 Node/npm。Node 的授权文本位于运行时的 `Node-LICENSE`。

## 目录与生命周期

默认目录是 `~/Library/Application Support/GlossaServer/`：

| 路径 | 内容 |
| --- | --- |
| `server-config.json` | 实例身份、独立同步/管理令牌、端口、备份和可选模型配置；权限 0600 |
| `runtime/` | 从应用内复制的 Node、服务和阅读端；运行不依赖工程工作目录 |
| `data/quiet-paper.sqlite` | 只追加的工程操作档案，包括完整 A、B、映射、历史及源快照 |
| `backups/` | 一致性 SQLite 快照及 SHA-256 清单 |
| `logs/` | 独立后台进程的标准输出/错误 |
| `service.plist` | 本实例的手动 launchd 启动配置 |

登录启动单独使用 `~/Library/LaunchAgents/local.glossa.sync.plist`。应用只控制自己配置对应的 `local.glossa.sync` 任务，不按端口终止其他进程。数据库由独立 SQLite 排他租约保护；第二个服务器或活动服务期间的恢复会被拒绝，崩溃由操作系统释放锁。

同步档案是增量的不可变操作日志；定期快照是完整数据库备份，并非另外一种省略旧 A 的精简格式。默认每 24 小时生成快照，保留最近 14 份已验证快照，可在界面调整。定时器位于独立服务内，客户端退出不影响它；Mac 关机或休眠期间不保证准点执行。

快照先通过 SQLite online backup API 生成，再做数据库、外键、模式、数量与 SHA-256 校验，落盘成功后才清理超过保留数的有效旧快照；损坏记录保留以供排查。恢复必须停服，先保存当前安全快照，再校验并原子替换；失败回滚。恢复前若服务正在运行，原生控制器会随后重新启动。客户端通过新服务世代重新发送手中较新操作，因此“恢复较早服务备份”不会强迫其他设备丢弃较新本地内容。

管理接口要求真实回环连接、独立管理令牌，拒绝任何带 Origin 的浏览器请求。同步令牌不能管理服务；恢复没有 HTTP 接口。配置及模型密钥只在当前用户的受限文件中保存，不放进 launchd 参数、连接分享文字或工程导出。

## 临时授权 AI 代理

先在“服务器配置 → AI 代理配置”配置兼容 Chat Completions 的完整地址（例如 `https://你的服务/v1/chat/completions`）、模型和 API 密钥，启用并保存。外部模型必须使用 HTTPS；回环模型允许 HTTP。地址固定在服务器所有者配置内，请求不能临时指定任意转发目标。

然后保存客户端同步连接，在笔记工具栏打开“临时 AI 转录”。界面会读取服务器实际模型地址与限制，用户逐次勾选对象、选择 30–300 秒有效期，再明确勾选本次明文授权。配置模型本身不等于授权发送笔记。只支持当前笔记中的文字、公式和原始笔迹采样，每次至多 32 个对象、1 MiB 明文。

客户端为本次授权生成 P-256 临时密钥，与服务器通过 ECDH/HKDF-SHA256 派生 AES-256-GCM 密钥。只发送选中对象的精确身份/版本与必要快照，不发送完整工程或长期 E2EE 口令。输入和候选响应均使用本次密钥认证加密；候选结果仅在本机预览或复制，不自动修改 A/B，也不冒充已确认的识别映射。

服务器在本次授权期间能读取所选明文，并将它发送给配置的模型提供者。撤销或到期会中止等待中的模型任务并清除服务器临时密钥和结果缓存；已经交付模型的内容无法通过撤销收回。审计仅保留有界内存中的授权身份、数量、时间和结果状态，不持久化正文或密钥；重启后授权失效。关闭面板会尝试撤销；网络不可达时界面明确说明等待短期授权过期。

普通同步和 E2EE 档案仍使用原有协议。`serverCanDecryptE2EE:false` 只表示服务没有长期档案解密密钥；启用代理后另有 `aiTemporaryPlaintextAccess:true` 表示明确授权的临时明文处理能力。没有模型配置时 `aiProxyAvailable:false`。

当前为忠实转录候选流程；真实模型的识别准确性和笔画到字符的精确映射尚未证明。测试使用真实 HTTP mock 模型，不消耗用户模型账户。

## 跨设备与命令行

界面管理的服务默认只监听 `127.0.0.1`。外部设备需要用户自己的 HTTPS 入口，部署方法见 [同步文档](SYNC.md)。应用不自动安装 VPN、开放路由器或发布公网入口。本轮本机验证不能代替实际局域网、公网和另一台实体设备的验收。

可从终端使用同一套管理逻辑：

```sh
GLOSSA_SERVER="$HOME/Library/Application Support/GlossaServer"
"$GLOSSA_SERVER/runtime/node" "$GLOSSA_SERVER/runtime/server/managed.mjs" \
  status --config "$GLOSSA_SERVER/server-config.json"
```

将 `status` 换成 `projects`、`backup` 或 `list-backups`。`verify-backup` 与停服后的 `restore` 还需 `--id 完整备份文件名`。输出为单行 JSON，不打印令牌。独立旧式 `npm run server` 仍可使用仓库中的环境变量配置，原生管理不会接管或迁移它；新备份调度与管理命令使用上述托管配置。

开发验证入口：`npm test`、`npm run test:swift`；构建后可在 macOS 运行 `node scripts/test-managed-launchd.mjs`，该脚本只创建临时目录和唯一 launchd 任务，并在结束后清理。实际执行记录见 [2026-10-23 服务器验收](verification/macos-server-2026-10-23/README.md)。
